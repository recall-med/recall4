## 1. Setup in one paragraph
Static front end on Cloudflare Pages (auto-deploy from `main`). Firebase Auth (Spark) for sign-in (Google + email). API = Pages Functions in `functions/api/*`, database = D1 `recall-db` (binding `DB`). `assets/js/sync.js` wraps the existing storage code. Switch: `config/sync-config.json` (`cloudEnabled`); `?cloud=1` forces it on per device. Cloud stores question IDs only; stats are derived from `attempts`. Everything must stay at $0.

## 2. Baseline (work from here)
```
cd backend-tests && npm install
node run.mjs                    # backend: expect 212 passed, 0 failed (+9: `/api/admin/commit` checks)
node run-frontend.mjs           # front end, all parts: expect 345 passed, 0 failed
node run-frontend.mjs pages     # only the pages/styles part: expect 118 passed, about 25 s
```
**Front-end tests are five independent parts** (`backend-tests/fe/`): `harness.mjs` (shared setup) + `part-sync` 51, `part-import` 23, `part-account` 55, `part-admin` 98, `part-pages` 118. `run-frontend.mjs` is a small runner: parts side by side on 4+ cores (`FE_PARALLEL=1/0` forces), one after another otherwise; one summary line per part; non-zero exit on any failure. Each part boots its own local site + D1 on its own ports (`FE_PORT`, `FE_GH_PORT`; runner uses 8789 + 10 per part) and creates what it needs, so any part runs alone and in any order (`node fe/part-pages.mjs`). After a page or style change run `pages`; run the rest only when sync, account or admin code changed (storage.js / sync.js / exam.js changes count: run all). `run.mjs` allows `TEST_JWKS` in `fe/harness.mjs` too.

Timing (this sandbox has ONE core, so parts cannot overlap here): sync 33 s, import 72 s, account 128 s, admin 85 s, pages 25-30 s; about 5 minutes in total, every part well under the 300 s single-command limit (run the whole thing in the background, see below).

Test traps learned:
- jsdom does not run `type="module"` scripts (the admin test extracts the inline module script and evals it); `/api/admin/summary` is cached 10 min (cache key `?v=2`, bump when the response shape changes); the suite uses the real `config/modules.json` with a tiny fixture `data/` (larynx = 6, pharynx = 4 questions): a test must never hard-code which module is ongoing, nor assume what other parts changed. The admin part hides `larynx` and edits `pharynx` in ITS OWN temp copy. Page tests read counts from the files in the temp site (`qCount`, `visTopics`) or from the exam they start (`ExamEngine.questions.length`), not from the repo's `data/`.
- Background processes: `(setsid nohup node ... > log 2>&1 &)` survives between tool calls; poll with `sleep N; grep -c "^PASS" log`. Plain foreground runs past 300 s are killed and leave `wrangler`/`workerd` running; kill by PID before the next run (`ps aux | grep -E "wrangler|workerd"`, `kill -9`), otherwise the next run fails sync checks with `pending=5 status=auth`.
- A test block that threw used to end the run with NO summary line. Parts now report it as `FAIL suite stopped early -> <stack>`.
- The shell is `sh`/mawk: no `time`, no `systime()` in awk. `pkill -f <name>` inside the same shell command kills the shell. jsdom reads the middle dot as two characters (match `·` with `\S{1,2}`). A page test that calls `App.navigate(...)` right after `.dashboard` first appears can lose a race with the app's own start-up render; wait about 1.5 s after load first. `npm install` creates `backend-tests/package-lock.json`; do not ship it.
- New: jsdom has both copies of a twice-drawn block (rail + phone: Stats list, Continue card); tests must use `querySelector` on a class, not ids. Test sandbox answers: use `ExamEngine.answer/goTo` + `App._submitExam()` in one `eval` instead of clicking.
- Headless Chromium works (Playwright for Python, `/opt/pw-browsers`; serve the repo with `python3 -m http.server`; no internet, so fonts and Firebase requests fail harmlessly). Measure layout and take screenshots there; the repo tests cannot see layout. Switch dark mode with `localStorage.dqb_theme`. Drive the app with `App.navigate(...)`; seed the Incorrect list by fetching real `data/**.json` questions into `localStorage.dqb_incorrect`.

## 7. Known risks and facts
- Unmeasured load; the tightest free limit is probably D1 writes (100k/day). The 60 exam uploads/hour/account limit exists. Practice runs (Retry incorrect, custom, Master) upload as attempts when they are single-module, which adds a little write load.
- `last_seen` is throttled to one write per 10 min and updates on any signed-in load, so it overstates "studying"; the dashboard uses attempts instead.
- Item stats come from `attempts.review` (stored only for exams up to 300 questions; imported guest exams excluded). Data is client-submitted, so treat it as approximate. Partial practice runs also land in `attempts`.
- The hour-of-day heat strip uses today's Cairo offset; it can be an hour off across daylight-saving changes.
- Hiding is display-level only: `data/**.json` and `config/modules.json` stay public URLs. `backend-tests/` and `db/schema.sql` are public on the live site (no secrets).
- A refresh ON the results page still goes to the dashboard (the in-memory result is not stored; only "View last attempt" / the attempts list survive).
- The results page for a long exam is still a long list (89 questions = about 7,500 px on a phone, collapsed rows); the chips and By topic are the navigation aids.
- CSS lessons: two rules of equal specificity are decided by file order (give variants two classes or move them below the base); a button that reuses `.icon-btn` inherits its backdrop blur and press-scale. Padding on a clipped grid item leaves a sliver when collapsed (put padding on an inner wrapper, see `.rv__pad`); a `display` rule beats the `hidden` attribute (add `[hidden]{display:none}`); rows hidden by a filter break `border-top` dividers (`UI.tidyList`). New: `@container` thresholds may be px (rem-only rule has this exception); inline `<span>`s in a flex row drop the space between them (use `gap` or `white-space: pre`); a `position: fixed` sheet must not sit inside an ancestor with transform/backdrop-filter (checked for `.csel`); the Incorrect-page `.select` rules are now dead for those three menus (the native select is hidden).
